# InterpLab · 口译自学训练与复盘工作台

浏览器端单用户口译训练工作台，覆盖**交替传译**、**带稿同传**、**无稿同传**、**影子练习**四种训练形态，以「智能分段 — 双轨记录 — 结构化复盘 — 个人成长追踪」为主轴。

> 所有素材、录音、复盘记录默认仅保存在**本机浏览器**（IndexedDB），不上传任何服务器。

## 功能

| 模块 | 能力 |
|---|---|
| 素材准备 | 上传音频（MP3/WAV/M4A）与**视频（MP4/MOV/WebM）**、波形预览、首尾静音裁剪、标签与难度标注、语速估算、**源语语言标注** |
| 素材分类 | 按源语语言（中文/英语/日语/韩语/法语/德语/俄语/西班牙语/阿拉伯语/其他）自动分组与筛选 |
| 素材导入 | 拖拽上传、**同名文件夹自动配对导入**、**直链下载导入**、**数据包（.ipkg）导入导出** |
| 智能分段 | VAD 静音检测 +「期望时长 ± 浮动」内按语义边界切分，边界置信度可见、可拖拽/合并/拆分 |
| 交传训练 | 逐段「听—记—译—录」、变速不变调、倒计时录音、数字笔记板 |
| 带稿同传 | **PPT 与文字稿分开上传、可同时存在**；默认只呈现稿件不跟随播放；Word 保留标题/段落/列表结构；幻灯片手动翻页并可全屏；含时间码字幕可开启跟随高亮；术语高亮、隐藏文本、遮挡训练 |
| 无稿同传 | 极简界面、EVS 目标提示、自报告标记、干扰音；可选挂 PPT/PDF 作为「看屏」参考 |
| 影子练习 | 源语/译语跟述、音位/片语、目标 EVS 与偏差曲线 |
| 复盘工作台 | 双轨波形严格对齐、源语/译语/混合/双耳分听、14 类问题锚点、可解释自动线索、视频回放 |
| 播放控制 | 全站统一倍速：0.25 / 0.5 / 0.75 / 1 / 1.25 / 1.5 / 1.75×，音频与视频同步变速不变调 |
| 个人成长 | 多轮趋势、问题分布、训练目标、连续天数与徽章 |
| 记录导出 | 训练记录 CSV、标记明细 CSV、全量 JSON、复盘报告（文本/PNG/打印 PDF）、**译语 MP3 音频（可自定义文件名）**、**数据包（素材+稿件+记录+术语库）** |
| 资源占用 | 左下角常驻监视器：JS 内存 / 站点存储 / 缓存条目 / DOM 节点；一键释放 objectURL、图片与 VAD 缓存、清理孤儿音频 |
| 训练界面 | 深色沉浸式「同传箱」布局：顶栏状态+计时、底栏大号传输控制、主区稿件/幻灯片、右侧可折叠战术面板 |

## 本地运行

```bash
cd frontend
pnpm install
pnpm dev        # http://localhost:5173
```

生产构建：

```bash
cd frontend
pnpm build      # 产物在 frontend/dist
pnpm preview
```

> **必须通过 http(s) 访问**，直接双击 `index.html` 无法使用录音与本地数据库。
> 录音需要浏览器授予麦克风权限，非 HTTPS 的远程地址会被浏览器拦截。

## 部署到 GitHub Pages

仓库已内置自动部署工作流 `.github/workflows/deploy.yml`：推送到 `main` 即自动构建并发布。

1. 在 GitHub 新建仓库（建议 public，Pages 免费额度不受限）；
2. 推送代码：

```bash
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git branch -M main
git push -u origin main
```

3. 打开仓库 **Settings → Pages**，把 **Source** 设为 **GitHub Actions**；
4. 等 Actions 里的 `Deploy InterpLab to GitHub Pages` 跑完即可访问。

`vite.config.ts` 里 `base: './'` 使用相对路径，因此无需按仓库名额外配置子路径。

### 当前线上地址与自定义域名

本仓库当前部署在用户站点 `terenceyb.github.io` 的自定义域名之下，属于 **project site（子路径）**：

| 用途 | 地址 |
|---|---|
| 正式地址 | https://blog.evanhub.cn/interplab/ |
| 旧地址 | `https://terenceyb.github.io/interplab/`（301 跳转到正式地址） |

**自定义域名绑在用户站点仓库 `terenceyb.github.io` 上，不在本仓库。**
因此本仓库**不应**添加 `CNAME` 文件——一旦加了，GitHub Pages 会把本仓库当成根站点，
抢走 `blog.evanhub.cn/` 根路径，导致同一域名下的博客站被覆盖。

原 `github.io` 地址返回 301 是 GitHub Pages 的强制行为：只要归属的用户站点绑定了自定义域名，
该域下所有 project site 都会跳转到自定义域名的对应子路径，无法单独关闭。换域名或回退该行为时，
需在 `terenceyb.github.io` 仓库的 Settings → Pages 中调整。

## 技术说明

- 前端：Vite + React 19 + TypeScript + Tailwind CSS v4 + shadcn/ui + Recharts
- 音频：Web Audio API / MediaRecorder 采集，Canvas 波形渲染，双轨播放器保证时间轴同步
- 存储：IndexedDB（`idb`），音频与结构化数据分离存储
- 无后端依赖：分段与评估线索全部在浏览器端计算

### 视频素材

视频与音频走同一套内核：`decodeAudioData` 解析音轨生成波形，VAD 分段、变速、双轨复盘全部复用；
画面由 `<video>` 元素承载（`VideoStage`），音频仍经统一播放器输出，因此**不存在两份声音**。

若某个视频的音轨无法解码（少见容器/编码），系统会退化为「按视频时长等分分段 + 无波形」，
并在素材上标记，仍可正常播放与训练。

### 关于素材导入方式

素材库支持三条路径：**拖拽 / 上传**、**本地文件夹批量导入**、**直链下载导入**（填 http(s) 直链直接抓取）。

百度网盘、阿里云盘的账号挂载功能已下线。原因不是没做，而是纯前端架构无法安全实现：

- 两家开放平台都要求「OAuth 授权码 → 换 access_token」，换取时必须携带 `app_secret` 并做服务端签名；
- 本站没有后端，把 secret 放进前端代码等于公开泄露；
- 两家的文件下载接口均不返回允许跨域的响应头（CORS），浏览器端无法直接拉取。

与其留一个点了必然失败的入口，不如去掉。网盘文件请先下载到本地文件夹，再用「本地文件夹」批量导入。

### 稿件与幻灯片格式支持

**幻灯片类**（按页呈现，手动翻页）：

| 格式 | 处理方式 |
|---|---|
| `.pptx` `.pptm` `.ppsx` `.potx` | 解析每页标题 / 要点 / 表格 / 配图 / 备注，以幻灯片形式手动翻页（← / → 或按钮），支持全屏看稿 |
| `.ppt` `.pps` | 自带 OLE 复合文档 + PowerPoint 二进制记录解析器，按 Slide 记录分页提取文字（含 CJK 与扩展区字符） |
| `.pdf` | pdf.js 逐页提取文字，按行聚合成段落；扫描件（无可提取文字）会明确提示改用 OCR 或 PPT/Word |
| `.odp` | 解析 `content.xml` 的 `draw:page` 分页文本 |

**稿件类**（连续文稿，保留排版）：

| 格式 | 处理方式 |
|---|---|
| `.txt` `.md` | 自动识别编码（UTF-8 / UTF-16 / GBK / GB18030 / Big5 / Shift_JIS / EUC-KR / windows-125x） |
| `.srt` `.vtt` `.ass` `.ssa` | 解析时间码后高置信对齐；可开启「跟随播放」按字幕高亮 |
| `.docx` | mammoth 转 HTML 后重建**标题 / 段落 / 列表 / 引用 / 表格行**结构，带稿同传按原排版呈现 |
| `.rtf` `.xml`(Word 2003) | 提取正文文字并切块 |
| `.doc` | 旧版二进制格式，浏览器无法解析，会提示另存为 `.docx` |

编码识别顺序：BOM → XML 声明 → UTF-8 严格校验 → jschardet 猜测 → GB18030 兜底；
OOXML 内部的 XML 也按此顺序解码，因此 WPS 导出的 GBK 声明文件不会再出现整页乱码。
导入后界面显示识别到的编码与解析来源，便于排查。

### 带稿同传的「跟随」行为

默认**只呈现稿件**，不随音视频进度高亮或滚动，避免被播放牵着走。只有导入含时间码的字幕
（SRT / VTT）后才出现「跟随播放」开关，打开即按时间码高亮；幻灯片以手动翻页呈现，不参与跟随。

### 两个上传入口（PPT / 稿件）

素材页与带稿同传页都把材料拆成两个独立入口：

- **PPT / PDF 幻灯片**：`.pptx .pptm .ppsx .ppt .pps .pdf .odp`
- **讲话稿 / 字幕**：`.docx .txt .md .srt .vtt .rtf`

两者可同时挂在一份素材上（实战中既看大屏又有讲稿），互不覆盖、可分别移除。
无稿同传只保留幻灯片入口——它是「看屏」，不是「念稿」。

### 数据包与文件夹导入

「数据与设置 → 数据包搬家」或「素材库 → 数据包」提供三种操作：

| 操作 | 说明 |
|---|---|
| 导入数据包 | `.ipkg` / `.zip`：含 `interplab.json` + `media/`，恢复素材、稿件、幻灯片、训练记录、术语库；ID 会重新分配，不与现有数据冲突 |
| 导入文件夹 | 选择本地文件夹，**同名文件自动配对**成一条素材并解析稿件 |
| 导出数据包 | 可选是否包含音视频；体积大会慢，但换设备可直接恢复 |

```
我的素材/
  拜登演讲.mp3  +  拜登演讲.docx   → 一条素材（音频 + 文字稿）
  峰会开幕.mp4  +  峰会开幕.pptx   → 一条素材（视频 + 幻灯片）
  记者会.mp3                        → 一条素材（仅音频）
```

### 内存与性能

纯前端应用的卡顿几乎都来自 objectURL、base64 图片和残留录音。本项目做了这些约束：

- 幻灯片配图存进 IndexedDB，只在渲染当前页时生成 objectURL（LRU 8 张，超出即 revoke）；
- 音频 objectURL 走 LRU 10 条，长会话不会持续累积；
- 波形峰值降到 2400 点（录音 1200 点），够画满整屏又不占内存；
- VAD 结果只缓存分析结果，不保留解码后的 `AudioBuffer`；
- 左下角资源监视器实时显示 JS 内存 / 站点存储 / 缓存条目 / DOM 节点，
  一键清理会释放 objectURL 与图片缓存、清空 VAD 与分段草稿，并删除没有任何素材引用的孤儿音频。

### 译语音频导出

复盘页「导出译语音频」会把本次训练的所有录音段合成为一个 MP3（44100Hz / 128kbps，
段间插入 0.4 秒静音便于分辨段落），文件名可自定义，默认格式：

```
YYYYMMDD-HHmm练习-素材名.mp3
例：20261109-1103练习-美国总统拜登演讲.mp3
```

MP3 编码在浏览器端用 lamejs 完成，不上传任何数据。

### 体积与按需加载

Word / PPT / PDF 解析、编码探测、MP3 编码均为**按需动态加载**：首屏主包约 1.2 MB（gzip 350 KB），
导入 `.docx` / `.pptx` / `.pdf` 时才拉取对应解析器，导出音频时才拉取编码器。
pdf.js 的 cmap 与标准字体以静态资源形式提供，只在中日韩 PDF 需要时按需请求。

### 关于自动评估线索

按 PRD 约束，自动指标**只提供线索、不给出总分**，措辞为「线索/参考信号」，并明确说明不能替代自我判断：

- **流利度**：停顿次数、平均停顿、发声时间比、长停顿位置（由录音能量包络计算）
- **覆盖率**：源语关键实体在译语转写中的命中情况
- **忠实度**：内容词重叠、数字匹配、高风险片段

覆盖率与忠实度需要「源语文本（稿件/字幕）」+「译语转写（可手填）」，缺失时界面会明确告知原因而非给出误导性数值。

## 数据与隐私

- 单用户产品，无教师端、班级、任务布置、互评、公开素材库与社交入口；
- 提供删除单条录音、删除素材及关联记录、删除全部数据入口；
- 支持导出训练记录与复盘报告用于归档迁移；
- 清理浏览器数据会导致本地内容丢失，请定期导出备份。
